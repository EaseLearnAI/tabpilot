# TabPilot 浏览器操作规范

TabPilot 在用户自己的 Chrome 里开一个专用窗口。**每个对话有自己独立的标签组**：插件会自动识别是哪个对话在调用，组名默认就是对话标题（类似 “🔎 X 研究” 这样的标签组），颜色自动错开。用户可以在旁边看，也可以随时接手。

## 标准流程

1. `group_status` —— 拿到“你的”标签组和里面的 tabId。组不存在会自动创建（自带一个空白页）。
   - 想要更短更贴切的组名，可以传 `task`（2–6 个词，比如 `"华为登录排查"`）。一般不用传。
   - 输出里“其他 TabPilot 组”属于别的对话，**绝对不要操作**。
2. `goto` 复用已有标签页去目标网址。**不要每一步都 `tab_open`**，只有确实需要同时看两个页面才新开。
3. `snapshot` 拿元素 ref（如 `e12`）→ `click` / `type` / `fill_form` 按 ref 操作 → 页面变化后重新 `snapshot`。优先用 ref，不用坐标。
4. **收尾（必须）**：浏览器部分做完就调用 `group_done`，关闭本对话的整组标签页。
   - 只有用户明确要看结果页 / 要接着手动操作时才用 `group_done(keep=true)`：标签保留、组折叠并标 ✓，不会被自动清理；并在回复里告诉用户去哪个组看。
   - 中途不再需要的标签页，用 `tab_close(tabId)` 随手关掉。

## 自动兜底（不要依赖它，但要知道）

- 每组最多 6 个标签页，超出时自动关闭最久没用的那个（结果里会提示）。
- 一个组 30 分钟没有任何操作会被自动关闭（用户正在看的组、`keep=true` 的组除外）。
- 对话归档或闲置结束时，插件的 SessionEnd Hook 会关闭该对话的组。
- 用户把某个标签页拖出组，或手动改了组名，就视为用户接管，TabPilot 不再关闭它。

## 安全

- 提交审核、发布、付款、删除、发送消息等不可逆操作前，先停下来让用户明确确认。
- 不要在对话里索要密码或验证码；需要登录时让用户在那个标签页里自己登录，然后继续。
